# Auditoria: riscos conhecidos

Lista viva dos riscos encontrados na auditoria de 2026-11-10 (branch `main` em `a7775fe`). Agentes e pessoas devem ler este arquivo junto com o `CLAUDE.md` para saber o estado atual do projeto.

## Como manter

- Ao resolver um risco, mude o status para **RESOLVIDO**, cite o commit ou PR e a data.
- Quando um risco for uma decisão consciente de não mexer agora, use **ACEITO** e explique o motivo.
- Riscos novos entram no fim da tabela com o próximo número. Não renumere.

Legenda: **ABERTO** (ainda existe) · **ACEITO** (decisão consciente, não é bug) · **MITIGADO** (não afeta o ambiente indicado hoje, mas precisa ser conferido de novo em outro ambiente) · **PRÉ-REQUISITO** (precisa estar resolvido antes ou dentro da branch indicada) · **A INVESTIGAR** (sintoma observado, causa desconhecida) · **RESOLVIDO**

Hashes: o `main` recebe cada PR por squash. Um hash citado num registro é o commit da PR no `main` (os do `git log --oneline` do `main`, que terminam em `(#N)`) ou um commit da PR citada no mesmo registro, que fica na aba de commits dessa PR no GitHub; os hashes atribuídos ao front são do carcheck-web.

Gravidade: quando o texto do risco começa com "Risco BAIXO", o impacto esperado é pequeno. A gravidade não é um status.
